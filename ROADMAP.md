# STEER roadmap

This roadmap communicates direction, not a promise of dates. Each deliverable still
requires a governed work item and the applicable STEER gates.

## 0.1 — Open foundation

- Publish the framework, platform, operating documents, templates, and pilot evidence.
- Adopt a permissive license, contribution policy, governance, security policy, and DCO.
- Separate vendor-neutral Core concepts from Federal BD project assumptions.
- Mark maturity and unsupported production boundaries honestly.

## 0.2 — Multi-POD reference platform

- Add organizations, PODs, projects, memberships, scoped roles, and project switching.
- Let one POD serve several projects and one organization operate several PODs.
- Add temporary, revocable specialist attachments for humans and agents.
- Add installation/bootstrap, configuration export, audit, and migration support.
- Prove tenant isolation, role authorization, accessibility, backup, and rollback.

## 0.3 — Adapter and conformance kit

- Publish stable contracts for work, code, communication, agent, CI, evidence, identity,
  secrets, deployment, and observability adapters.
- Provide reference adapters for the tools used by this project without making them
  mandatory for other adopters.
- Publish conformance fixtures and a compatibility report.

## 0.4 — Evidence and self-optimization

- Run the predeclared STEER-versus-control cohort across several work types.
- Expose outcome yield, verified release time, qualified human attention, cost, rework,
  bypasses, defects, and trust/cognitive-load measures.
- Turn repeated failure modes into versioned guardrails with bounded change limits.

## 1.0 — Stable community distribution

- Freeze a versioned Core specification and supported migration path.
- Publish deployable releases, upgrade/rollback tooling, support boundaries, SBOMs,
  security response targets, and a compatibility/trademark policy.
- Establish multi-maintainer governance and at least two independent adopter reports.

## Not promised

STEER will not claim universal superiority from one pilot, hide failed experiments, make
one vendor mandatory, let agents approve human gates, or optimize delivery speed by
weakening safety and quality guardrails.
